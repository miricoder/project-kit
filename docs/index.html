The pipeline

Eleven phases, each owned by one skill. A phase hands off to the next only after recording what it produced; the next skill reads that record and refuses if a precondition is unmet. Gates are decided by scripts, never asserted by a model.

/pipeline

✔ shipped

The conductor — not a phase. Drive and inspect the Project Kit product pipeline — report which phase a project is in, what may run next, and run or offer the next skill. Also sets the run mode (manual, auto, yolo) and the budget cap. Use when the user says /pipeline, "what's next", "where are we", "resume this project", "set mode to yolo", "run the pipeline", or asks about a project's phase, gate or judge status.

Reads & writes pipeline.json, ~/.claude/project-kit/registry.json

/ideate

✔ shipped

Research and frame a raw product idea — prior art, the user and the job, how it would work, what is uncertain — and write it up as research.md. The first phase of the Project Kit pipeline. Use when the user says /ideate, "I have an app idea", "I want to build something that...", "research this idea", or describes a product they are thinking about building.

Reads the user's idea
Writes docs/research.md

/proposal

✔ shipped

Turn research into a scoped proposal — what v1 is, what it explicitly is not, what it costs and how long it takes. The scope-and-money decision point of the Project Kit pipeline. Use when the user says /proposal, "scope this", "what would v1 be", "cut this down", or after /ideate completes.

Reads research.md
Writes docs/proposal.md

/design

✔ shipped

Turn an accepted proposal into a full-stack technical spec plus executable Gherkin acceptance criteria — architecture, data model, interfaces, failure modes and rollback. The last phase before the independent judge panel. Use when the user says /design, "design this", "write the spec", "how should this be built", or after /proposal is accepted.

Reads proposal.md
Writes docs/spec.md, docs/acceptance.feature

Run modes

ModeBehaviourStops
manualStops after every phase and offers a menuevery phase
auto (default)Advances between phases, stopping at the four checkpoints4 checkpoints
yoloEnd to end with no pipeline stops, subject to the budget capnone

The four auto checkpoints: after /ideate (is this the idea?), after /proposal (accept scope and cost?), before the judge panel runs (this spends API credit), and after /verdict (accept the ruling, or revise?).

The budget cap is not a checkpoint. It halts the run in every mode, including yolo.
